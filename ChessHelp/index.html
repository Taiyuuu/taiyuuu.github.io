System Introduction

Chess.io is a lightweight, embedded-focused Python chess engine designed for handheld gaming microcontrollers (e.g., PyBadge, ESP32 Python runtimes, or retro handheld consoles). It transforms minimalist text display screens into a competitive chess console with full FEN validation, move history tracking, cloud synchronization, and dual engine support.

🧠

Maia-3 AI Engine

Integrates human-like AI trained on millions of online games to match human mistake profiles at custom ELO levels (600 - 2600).

⚡

Stockfish Integration

Connects via REST API to evaluate board positions, compute win probabilities, and provide dynamic move hints in real time.

☁️

Cloud Game Replay

Stores completed games on Firebase with unique game IDs. Allows full step-by-step PGN board replay directly on the device console.

Key technical components include:

  • Local Move Engine: Custom mathematical implementation of pseudo-legal move generation, king check verification, castling, and en passant logic written in pure Python without heavy external library requirements on the microcontroller.
  • FastAPI Microservice: Encapsulates maia3-uci using Python's chess.engine module, protected by custom API keys (X-API-Key).
  • Hybrid Eval Pipeline: Because Maia-3 focuses purely on human move prediction, every Maia move automatically triggers a background Stockfish evaluation query to update the UI's centipawn eval and win chance meters.

Common Issues & Troubleshooting

1. Initial API Request Delays (Server Cold Start / Sleep)

Symptom: When making the first move against Maia-3 after several minutes of inactivity, the device may freeze or feel unresponsive for 30–50 seconds.

Cause: The free tier on Render automatically spins down Web Services after 15 minutes of inactivity. When a new move is requested, the server must wake up, load PyTorch, and cache the maia3-5m model weights into memory.

Workaround / Solution: Send a health-check ping to /health when opening the game, or configure a periodic cron job (e.g. via UptimeRobot) to ping your endpoint every 10 minutes to keep the server warm.

2. "API request failed: 500 Internal Server Error"

Cause: Usually caused if the underlying UCI engine process fails to start or if maia3-uci binary permissions are revoked during continuous container deployment.

Solution: Ensure your Dockerfile includes RUN chmod +x /app/maia3-uci and verify that shutil.which("maia3-uci") properly detects the executable in PATH.

3. "Illegal Move!" Message on Custom Replay

Cause: Happens if PGN movetext contains non-standard notation or broken castling rights when importing games recorded outside of Chess.io.

Solution: Ensure games saved to Firebase are constructed strictly using the device's built-in build_pgn_movetext() exporter.
